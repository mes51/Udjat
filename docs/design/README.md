# Udjat デザインシステム

Udjat の UI を作る・直す時の指針。トークンの実体は `src/renderer/src/index.css` の `@theme`、部品の実装は `src/renderer/src/components/ui/`。値の一覧は [tokens.md](tokens.md)、部品ごとの使い分けは [components.md](components.md)。ブラウザで見られる版(色見本と部品のプレビュー)は公開ページ(README 末尾のリンク)にある。

## 何のための画面か

LAN 上の LLM サーバーに、動画やファイルを添えて長い会話をするための作業机。1 日に何時間も開いたままにする道具なので、次を優先する。

1. **本文が主役**: モデルの返答とユーザーの入力以外は一段引く。装飾は情報を運ぶものだけ
2. **状態が一目で分かる**: 生成中・承認待ち・常駐モデル・エラーは、文章を読まなくても形と色で分かる
3. **長時間見ていて疲れない**: 純黒・純白・高彩度を避け、面の差で階層を作る
4. **両テーマで同じ品質**: ダークが基本だが、ライトは「反転」ではなく同じ役割のトークンを別の値で満たす

## 面と線

面は 4 段。上に乗るものほど明るい(ライトでは順に暗く・濃くなる)。

| トークン    | 役割                     | 例                                       |
| ----------- | ------------------------ | ---------------------------------------- |
| `surface`   | 地。会話の本文が載る     | チャット領域、空状態                     |
| `surface-2` | パネル。地から一段上がる | サイドバー、会話設定、入力欄、ダイアログ |
| `surface-3` | 浮いた要素・hover        | カード、チップ、選択行の hover           |
| `surface-4` | 押下・コード・強調した面 | ボタン押下、`code`、kbd                  |

枠線(`border`)は「面の差だけでは境界が分からない所」にだけ引く。カードの四辺・行の区切り・入力欄の縁がそれで、パネル同士の境界は 1 本の線で十分。`border-strong` は hover や区切りを強めたい時だけ。

影は 2 種類。`shadow-panel` は入力欄のように地の上で少しだけ浮くもの、`shadow-overlay` はダイアログ・メニュー。カードや行に影は付けない。

## 色の役割

- **アクセント(琥珀 `accent`)**: 操作と選択の 1 色。主ボタン、選択中の行、リンク、フォーカスリング、ON のチップ、進行中の点。名前の由来(ホルスの目)に寄せた。1 画面に主ボタンは 1 つまで
- **意味色**: `success`(完了・常駐)、`warning`(注意・権限の宣言)、`danger`(エラー・削除・拒否)、`info`(補足)。状態を伝える時だけ使い、装飾には使わない。アクセントと意味色は役割が違うので、同じ要素に両方を使わない
- **文字**: `fg`(本文)、`fg-muted`(補助・ラベル)、`fg-subtle`(メタ情報・placeholder)。本文より薄い文字は 2 段まで。`opacity` で薄くしない(トークンを使う)

意味色の薄い面が要る時は `bg-danger/10` のようにトークンに透過を掛ける。独自の赤や緑を直接書かない(`text-red-400` などは使わない)。

## 文字

- 書体は OS のもの(`--font-sans`)。ポータブル配布なのでフォントは同梱しない。等幅は `--font-mono`(ツール名、モデル id、コード)
- サイズは 6 段だけ: **11px** メタ情報(時刻・使用量)、**12px** ラベル・チップ、**13px** UI の本文(設定、ツールカード)、**14px** 一覧・フォーム、**15px** チャット本文、**16px** ダイアログの見出し
- 行間は本文 1.75、UI 1.5。数字が並ぶ所は `tabular-nums`
- 太さは 400 と 600 の 2 つ。500 はボタンのラベルだけ

## 間隔と角丸

- 間隔は 4px 刻み。要素の間は `gap`、外周は `padding`。兄弟間に個別の `margin` を足さない
- 角丸は役割で決める: `sm`(6px)入力欄・チップ・kbd、`md`(8px)ボタン・カード・行、`lg`(12px)ダイアログ・パネル、`xl`(14px)入力欄の外枠。`rounded-full` はチップと点だけ
- 一覧の行の高さは 32px を基準にし、hover は面(`surface-3`)、選択は `accent-soft`

## 動き

- 色の変化は 150ms。位置を動かすアニメーションは使わない(生成中の点滅と読み込みの回転だけ)
- `prefers-reduced-motion` では止める(index.css で一括)

## 言葉

- 操作はその結果を言う: 「送信」「保存」「許可」「ここから分岐」。「OK」「はい」だけのボタンを作らない
- エラーは何が起きて何をすればよいかを 1 文で。謝らない、曖昧にしない
- 英語の専門語は無理に訳さない(`temperature`、`top_p`、MCP)が、説明文は日本語で書く
- 半角と全角の間にスペースを入れる(「Ctrl+N 新しい会話」「30 秒」)

## 新しい画面を作る時の手順

1. どの面に載るかを決める(地か、パネルか)。それで背景と枠線が決まる
2. 主操作を 1 つ決めて `Button` の default にし、残りは secondary / ghost
3. 状態(読み込み中・エラー・空)を最初から設計する。空状態は次に何をすればよいかを書く
4. ライトテーマでも確認する(設定 → 一般 → テーマ)
5. 新しい色や角丸が要ると思ったら、まずトークンで表せないか考える。要るならトークンを足して [tokens.md](tokens.md) に書く

## アイコン

- ホルスの目(ウジャト)を琥珀のグラデーションで描いた SVG(`resources/icon.svg`、ユーザー提供)がアプリのアイコン。アクセント色の由来でもある
- 派生物は `node scripts/make-icons.mjs` で生成する: `build/icon.ico`(exe / タスクバー、16〜256px)、`build/icon.png`(1024px)、`resources/icon.png`(開発時のウィンドウ用、256px)。UI 内では `src/renderer/src/assets/udjat.svg` を使う(未選択時のワードマーク)
- 正方形に収める時は周囲に 6% の余白を取り、比率は保つ。背景は透明のまま(ダーク / ライト両方に置かれる)
